# Справка по API GroundLink

> Пример из портфолио. GroundLink — вымышленный сервис. Эта страница показывает, как я структурирую
> справку по REST- и WebSocket-API. Здесь не описаны реальные системы, эндпоинты или данные клиентов.
>
> Это Markdown-исходник, из которого собрана HTML-страница справки.

Бронируйте сеансы связи наземной станции и получайте телеметрию космических аппаратов.

## Обзор

API GroundLink даёт программный доступ к сети наземных станций. С его помощью можно находить
космические аппараты, доступные для отслеживания, бронировать сеансы связи на конкретной антенне
и получать телеметрию в реальном времени во время пролёта.

API использует два транспорта:

| Транспорт | Назначение | Базовый адрес |
|---|---|---|
| REST поверх HTTPS | Запросы к каталогу и операции бронирования | `https://api.groundlink.example/v1` |
| WebSocket поверх TLS | Непрерывная передача телеметрии во время пролёта | `wss://stream.groundlink.example/v1` |

Все запросы и ответы используют `application/json`. Все метки времени указаны в UTC в формате
ISO 8601, например `2026-03-14T09:20:00Z`.

Машиночитаемая спецификация REST-части — [openapi.yaml](openapi.yaml) (OpenAPI 3.0).

## Аутентификация

API использует аутентификацию по bearer-токену. Передавайте токен в заголовке `Authorization`
в каждом запросе.

```
Authorization: Bearer <access_token>
```

Получить токен можно в консоли оператора, в разделе **Access keys**.

| Свойство | Значение |
|---|---|
| Срок жизни токена | 12 часов |
| Права доступа (scopes) | `catalog:read`, `schedule:write`, `telemetry:read` |
| Транспорт | Только HTTPS. Запросы по обычному HTTP отклоняются. |

> **Не встраивайте токены в клиентские приложения.** Токен даёт все назначенные ему права.
> Храните токены на стороне сервера и меняйте их, если есть подозрение на компрометацию.

Для WebSocket-эндпоинта передавайте тот же токен как query-параметр, потому что браузерные
WebSocket-клиенты не могут задавать собственные заголовки:

```
wss://stream.groundlink.example/v1/telemetry?access_token=<access_token>
```

## Лимиты запросов

| Область | Ограничение |
|---|---|
| Запросы к каталогу | 120 запросов в минуту на токен |
| Запросы бронирования | 30 запросов в минуту на токен |
| Подключения телеметрии | 4 одновременных подключения на токен |

При превышении лимита API возвращает `429 Too Many Requests` с заголовком `Retry-After`, который
указывает, сколько секунд подождать перед повтором.

## Список аппаратов

Возвращает космические аппараты, которые ваша организация вправе отслеживать, с ближайшим
прогнозируемым пролётом для каждого.

```
GET https://api.groundlink.example/v1/satellites
```

### Query-параметры

| Параметр | Тип | Описание |
|---|---|---|
| `status` | string | Фильтрует результат по состоянию аппарата: `operational`, `commissioning`, `maintenance`, `decommissioned`. Если не указан, возвращаются все состояния. |
| `station_id` | string | Возвращает только аппараты, видимые с указанной наземной станции. |
| `limit` | integer | Максимальное число записей в ответе. Диапазон 1–200. По умолчанию 50. |
| `cursor` | string | Курсор пагинации из поля `next_cursor` предыдущего ответа. |

### Пример запроса

```bash
curl --request GET \
  'https://api.groundlink.example/v1/satellites?status=operational&limit=2' \
  --header 'Authorization: Bearer <access_token>'
```

### Ответ 200 OK

| Поле | Тип | Описание |
|---|---|---|
| `items` | array | Список записей об аппаратах. |
| `items[].satellite_id` | string | Идентификатор аппарата в GroundLink. |
| `items[].norad_id` | integer | Публичный каталожный номер объекта. |
| `items[].name` | string | Отображаемое название аппарата. |
| `items[].status` | string | Текущее состояние аппарата. |
| `items[].next_pass` | object | Ближайший прогнозируемый пролёт. `null`, если в ближайшие 72 часа пролёт не прогнозируется. |
| `items[].next_pass.station_id` | string | Наземная станция, которая увидит пролёт. |
| `items[].next_pass.aos` | string | Начало связи (AOS), UTC. |
| `items[].next_pass.los` | string | Потеря связи (LOS), UTC. |
| `items[].next_pass.max_elevation_deg` | number | Максимальный угол места аппарата за пролёт, в градусах. |
| `next_cursor` | string | Курсор следующей страницы. `null` на последней странице. |

```json
{
  "items": [
    {
      "satellite_id": "sat_7Kq2",
      "norad_id": 49001,
      "name": "Kestrel-1",
      "status": "operational",
      "next_pass": {
        "station_id": "gs_north",
        "aos": "2026-03-14T09:20:00Z",
        "los": "2026-03-14T09:31:40Z",
        "max_elevation_deg": 61.4
      }
    },
    {
      "satellite_id": "sat_M3ba",
      "norad_id": 49014,
      "name": "Kestrel-2",
      "status": "operational",
      "next_pass": null
    }
  ],
  "next_cursor": "eyJvIjoyfQ"
}
```

### Ошибки

| Код | Причина | Что делать |
|---|---|---|
| 400 Bad Request | Query-параметр задан неверно или вне диапазона, например `limit=500`. | Сверьте значения параметров и повторите запрос. |
| 401 Unauthorized | Заголовок `Authorization` отсутствует, задан неверно или токен истёк. | Получите новый токен и повторите запрос. |
| 403 Forbidden | У токена нет права `catalog:read`. | Запросите это право у администратора организации. |

## Бронирование сеанса связи

Резервирует антенну на один пролёт. Запрашиваемый интервал должен попадать внутрь прогнозируемого
пролёта из метода «Список аппаратов», а антенна должна быть свободна на этот интервал.

```
POST https://api.groundlink.example/v1/schedules
```

### Тело запроса

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `satellite_id` | string | Да | Аппарат, с которым нужно установить связь. |
| `station_id` | string | Да | Наземная станция, которую нужно зарезервировать. |
| `start` | string | Да | Начало сеанса, UTC. Не раньше AOS пролёта. |
| `end` | string | Да | Конец сеанса, UTC. Не позже LOS пролёта. |
| `purpose` | string | Нет | Одно из: `telemetry`, `command`, `payload_download`. По умолчанию `telemetry`. |
| `priority` | integer | Нет | Диапазон 1–5, где 1 — наивысший. По умолчанию 3. |

### Пример запроса

```bash
curl --request POST \
  'https://api.groundlink.example/v1/schedules' \
  --header 'Authorization: Bearer <access_token>' \
  --header 'Content-Type: application/json' \
  --data '{
    "satellite_id": "sat_7Kq2",
    "station_id": "gs_north",
    "start": "2026-03-14T09:22:00Z",
    "end": "2026-03-14T09:30:00Z",
    "purpose": "payload_download",
    "priority": 2
  }'
```

### Ответ 201 Created

| Поле | Тип | Описание |
|---|---|---|
| `schedule_id` | string | Идентификатор брони. Используется для открытия потока телеметрии. |
| `state` | string | `confirmed`, если антенна зарезервирована, `pending`, если запрос конкурирует с бронью более высокого приоритета. |
| `satellite_id` | string | Аппарат, которому принадлежит сеанс. |
| `station_id` | string | Зарезервированная наземная станция. |
| `start` | string | Подтверждённое начало сеанса, UTC. |
| `end` | string | Подтверждённый конец сеанса, UTC. |
| `created_at` | string | Время создания брони, UTC. |

```json
{
  "schedule_id": "sch_R48tvQ",
  "state": "confirmed",
  "satellite_id": "sat_7Kq2",
  "station_id": "gs_north",
  "start": "2026-03-14T09:22:00Z",
  "end": "2026-03-14T09:30:00Z",
  "created_at": "2026-03-13T15:02:11Z"
}
```

> **Бронь не окончательна, пока не подтверждена.** Если `state` равно `pending`, опрашивайте бронь,
> пока она не станет `confirmed` или `rejected`. Не открывайте поток телеметрии для неподтверждённой брони.

### Ошибки

| Код | Причина |
|---|---|
| 400 Bad Request | Не указано обязательное поле или интервал некорректен (например, `end` раньше `start` или окно вне пролёта). |
| 401 Unauthorized | Токен отсутствует или истёк. |
| 403 Forbidden | У токена нет права `schedule:write` либо нет доступа к станции. |
| 409 Conflict | Антенна уже забронирована на пересекающийся интервал равным или более высоким приоритетом. |
| 429 Too Many Requests | Превышен лимит запросов на бронирование. |

## Подписка на телеметрию

Открывает WebSocket-соединение, которое передаёт кадры телеметрии во время забронированного пролёта.
Кадры приходят по мере приёма наземной станцией, обычно с частотой 1 Гц.

```
WSS wss://stream.groundlink.example/v1/telemetry?access_token=<access_token>
```

### Открытие потока

После установки соединения отправьте сообщение подписки:

```json
{
  "action": "subscribe",
  "schedule_id": "sch_R48tvQ",
  "channels": ["power", "attitude"]
}
```

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `action` | string | Да | `subscribe` или `unsubscribe`. |
| `schedule_id` | string | Да | Подтверждённая бронь. Должна быть в состоянии `confirmed`. |
| `channels` | array | Нет | Каналы: `power`, `attitude`, `thermal`, `payload`. Если не указаны, передаются все доступные. |

Сервер подтверждает подписку:

```json
{
  "type": "subscribed",
  "schedule_id": "sch_R48tvQ",
  "channels": ["power", "attitude"]
}
```

### Кадры телеметрии

```json
{
  "type": "telemetry",
  "schedule_id": "sch_R48tvQ",
  "received_at": "2026-03-14T09:22:03Z",
  "channel": "power",
  "values": {
    "bus_voltage_v": 27.8,
    "battery_soc_pct": 84,
    "solar_array_current_a": 3.12
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `type` | string | Тип сообщения: `subscribed`, `telemetry`, `pass_ended`, `error`. |
| `received_at` | string | Время приёма кадра наземной станцией, UTC. |
| `channel` | string | Канал, к которому относится кадр. |
| `values` | object | Измерения канала. Имена полей и единицы зависят от канала. |

Когда аппарат уходит за горизонт, сервер присылает финальное сообщение и закрывает соединение:

```json
{
  "type": "pass_ended",
  "schedule_id": "sch_R48tvQ",
  "los": "2026-03-14T09:30:00Z",
  "frames_delivered": 478
}
```

### Обработка соединения

| Ситуация | Поведение сервера | Что должен делать клиент |
|---|---|---|
| Простой соединения | Ping-кадр каждые 30 секунд. | Отвечать pong. Соединения, пропустившие два ping, закрываются. |
| Разрыв сигнала во время пролёта | Прекращает передачу кадров, соединение держит открытым. | Ждать. Разрывы в несколько секунд на низком угле места — это норма. |
| Обрыв соединения посреди пролёта | Буферизует до 60 секунд кадров. | Переподключиться и подписаться заново. Буфер воспроизводится один раз. |
| Пролёт завершён | Присылает `pass_ended`, затем закрывает с кодом `1000`. | Не переподключаться по этой брони. |

### Коды закрытия соединения

| Код | Значение | Что делать |
|---|---|---|
| `1000` | Пролёт завершён штатно. | Ничего. |
| `4001` | Токен отсутствует, недействителен или истёк. | Получить новый токен и переподключиться. |
| `4003` | Нет права `telemetry:read` либо бронь чужой организации. | Проверить право и `schedule_id`. |
| `4009` | Бронь не в состоянии `confirmed`. | Дождаться подтверждения и переподключиться. |
| `4029` | Слишком много одновременных подключений для токена. | Закрыть существующий поток и переподключиться. |

## Коды ошибок

Ошибки REST имеют единый формат ответа:

```json
{
  "error": {
    "code": "window_conflict",
    "message": "The requested interval overlaps a confirmed reservation.",
    "request_id": "req_9f2c1b"
  }
}
```

Указывайте `request_id` при обращении в техподдержку — он идентифицирует конкретный запрос в логах сервера.

| HTTP-статус | Код | Причина |
|---|---|---|
| 400 | `invalid_parameter` | Параметр задан неверно или вне диапазона. |
| 400 | `window_outside_pass` | Запрошенный интервал не входит в прогнозируемый пролёт. |
| 401 | `token_expired` | Токен доступа больше не действителен. |
| 403 | `scope_missing` | У токена нет необходимого права. |
| 404 | `not_found` | Нет аппарата, станции или брони с указанным идентификатором. |
| 409 | `window_conflict` | Антенна уже забронирована на пересекающийся интервал. |
| 429 | `rate_limited` | Превышен лимит запросов для этой области. |
| 500 | `internal_error` | Непредвиденный сбой на стороне сервера. Повторить с экспоненциальной задержкой. |

## Глоссарий

| Термин | Определение |
|---|---|
| AOS | Acquisition of signal, начало связи. Момент, когда наземная станция впервые устанавливает радиосвязь с аппаратом во время пролёта. |
| LOS | Loss of signal, потеря связи. Момент, когда радиосвязь прерывается, обычно когда аппарат уходит за горизонт. |
| Сеанс связи | Интервал, зарезервированный на конкретной антенне для связи с конкретным аппаратом. |
| Угол места (elevation) | Угол между горизонтом и аппаратом, в градусах. Чем выше, тем обычно устойчивее связь. |
| Наземная станция | Площадка с одной или несколькими антеннами для связи с космическими аппаратами. |
| ISO 8601 | Международный формат даты и времени. Этот API использует UTC с завершающим `Z`. |
| NORAD ID | Публичный каталожный номер объекта на околоземной орбите. |
| Пролёт (pass) | Период, в течение которого аппарат виден с данной наземной станции. |
| Кадр телеметрии | Один набор измерений, переданный аппаратом в один момент времени. |
